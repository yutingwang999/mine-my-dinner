# Phase 1 Carryover

Decisions, warnings, and open items from Phase 0 and the Phase 1 plans, kept in this committed file so they reach later planning. The execution ledgers live only on the developer's machine, so anything not carried here or into the other docs does not survive them. Items that changed the product's behavior are folded into `design.md`. Read this file together with the still-open table in `phase-0-import-feedback.md` when writing each plan.

## How to read this file

Every item starts with its status. The statuses were checked against the code and the git history on 2026-11-24; an item marked `Open` has no sign of being done, and a status line under an item says what was found.

| Status | Meaning | Where it is |
|---|---|---|
| `Open` | Still to do. The arrow (→ ...) names where it goes next. | In the section's list |
| `Check` | The code no longer matches the text, or it cannot be checked from the code; the user decides. | In the section's list |
| `Note` | A standing rule, caveat or known limitation; nothing to do unless it starts to matter. | In the section's list |
| `Watch` | Seen in an evaluation and not yet a defect; looked at again in the named rounds. | In the section's list |
| `Done` | Done; the status line says where. | Folded under "Closed items" at the end of its section |
| `Superseded` | No longer applies, usually because plan 3b-2 replaced the revise step. | Folded under "Closed items" |
| `Won't do` | Decided not to do. | Folded under "Closed items" |
| `Record` | Kept as a record of results or of a past decision. | Folded under "Closed items" |

A new item gets a status when it is added. When an item is done, change its status, add a status line, and move it under its section's "Closed items".
